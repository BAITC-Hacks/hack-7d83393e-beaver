# Бюджет спринта: 120 минут

Это план распределения усилий команды, не гарантия сроков и не оценка
производительности моделей. Подготовка с нуля больших весов может не уложиться.

| Минуты | Работа | Контрольная точка |
|---|---|---|
| 0–10 | Проверить локальный ASR, диаризацию и LLM; зафиксировать контракт и интерфейсы | Пробная запись проходит модели; нет внешних вызовов |
| 10–55 | A: речь; B: поручения; C: интерфейс; D: экспорт/проверки | Модули выдают общий формат; ошибки явные |
| 55–80 | Интеграция одного реального файла, устранение несовместимостей | Файл → голоса → поручения → DOCX |
| 80–100 | RU, KK, MIX, перенос срока, пропущенный реквизит; устранение багов | Фактические результаты сохранены |
| 100–120 | README, проверка без внешней сети, защита и резервная демонстрация | Повторяемый запуск, честная матрица требований |

## Сокращение объёма
Сначала отключить видео, затем потоковую обработку, затем PDF (DOCX остаётся),
затем косметику и уведомления. Не вырезать казахский, смешанную речь,
диаризацию, поручения и экспорт ради эффектной картинки.
После 80-й минуты новые функции не добавлять.

## Диагностика начальных блокеров
- Нет весов: не обещать автономность и не подменять внешним API.
- pyannote не запускается: это блокер обязательной диаризации, не скрывать
  ручными метками. Изолировать зависимость в отдельной среде при возможности.
- Слабое железо: короткий файл, последовательный запуск, измерить время;
  не заявлять realtime.
- Вся ML-часть недоступна: можно показать только явно обозначенный UX-пример;
  он не считается выполнением обязательного сценария.
