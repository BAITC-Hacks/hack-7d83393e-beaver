# Задание агенту независимой приёмки

Работай после фиксации базовой реализации. Твоя задача — воспроизводимо найти
несоответствия, а не подтвердить обещания автора. Не делай оценок в баллах.
Не изменяй приложение, golden-данные и критерии ради PASS.

1. Создай чистую рабочую копию и запусти bootstrap по README.
2. Используй новый набор вымышленных записей/текстов, не только витринный пример.
3. Проверь обязательные требования и новые функции на API и через браузер.
4. Разделяй структурные тесты и настоящие inference-тесты; отмечай данные.
5. Выполни тест с изменёнными именами/датами/именем файла. Проверь отсутствие
   хардкода результатов, автоматического fixture fallback и утечки golden.
6. Проверь неподтверждённый перенос, согласованный перенос, отказ, отмену,
   исполнителя не равного говорящему, неизвестного исполнителя и срок без даты.
7. Проверь prompt injection в транскрипте как недоверенные данные, XSS,
   произвольные пути/URL, лимит загрузки, безопасные ошибки и логи.
8. Выполни изоляцию сети без изменения глобальных политик. Не называй
   обходом отсутствие наблюдаемых обращений. Нет разрешённой изоляции — NOT RUN.
9. Приведи минимальное воспроизведение каждой проблемы и требование, которое
   нарушено. Передай интегратору; после исправления повтори тот же тест.
10. Проверь README по фактическим командам, а не по наличию текста.

Качество казахских/смешанных natural-аудио эталонов должно проверяться
владеющим обоими языками разметчиком. Без такой проверки не выдавай
автосгенерированные эталоны за экспертную оценку языка.

Не заявляй независимость сильнее фактической: новый агент той же команды
не равен внешней сертификации, а доступные разработчикам случаи не hidden-test.
Используй PASS/FAIL/NOT RUN с артефактами и оставшимися ограничениями.
