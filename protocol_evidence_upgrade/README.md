# Усиление проекта: «Протокол с проверяемыми поручениями»

## Начать разработку
Распакуйте каталог в рабочий репозиторий и передайте основному кодинг-агенту
START_COMPETITIVE.md. Предыдущие задания автономной установки и загрузки моделей
сохранены в hackathon_agent_pack/. Не нужно запускать несколько главных агентов.

## Что добавлено
Три связанные функции: основания каждого поля, типизированная история с
временными срезами и вопросы перед утверждением. COMPETITIVE_SPEC.md задаёт
сценарий и отличает реализованный reference core от будущего полного продукта.
EVALUATOR_GUIDE.md описывает проверяемый интерфейс и артефакты без обещаний баллов.
INDEPENDENT_QA_AGENT.md — задание отдельному проверяющему агенту.

## Реальный код, а не только промпт
В reference_core/ есть исполняемые валидатор, журнал событий, FastAPI,
веб-стенд и JSON→DOCX. Проверены 80 unit/contract/API/export случаев.
Артефакты и границы: reference_core/reports/ и BUILD_STATUS.md.
Примеры — синтетические, без реальных данных. Модели не скачаны и не подключены.
Этот стенд НЕ заменяет обязательные ASR, диаризацию и LLM.

Проверка reference core:
```bash
cd reference_core
python -m pip install -r requirements.txt
python scripts/verify_reference.py
python -m evidence_core serve --port 8765
```

Адрес при запущенном сервере: http://127.0.0.1:8765.
Сервер из среды подготовки не размещён в интернете и не запущен на компьютере
пользователя. Здесь HTTP-старт проверен, затем тестовый процесс остановлен.

Главная задача следующего кодинг-агента — подключить настоящие модели,
замкнуть аудио→документ и пройти новые испытания, а не улучшать витрину fixtures.
