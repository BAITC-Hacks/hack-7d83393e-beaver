# Навигация для независимой проверки

Этот файл описывает интерфейсы и границы проверки, не запрашивает оценку.
Формат проверки организаторов неизвестен. Инструкции ниже — предлагаемый
единый интерфейс будущего приложения, а не утверждение, что оно уже реализовано.

## Что находится в этом архиве сейчас
- hackathon_agent_pack/: ранее подготовленные инструкции автономной сборки.
- reference_core/: исполняемая проверка структур, replay размеченных событий,
  локальное API, интерфейс стенда и экспорт импортированного снимка в DOCX.
- reference_core/reports/: фактические результаты выполненных проверок ядра.
- COMPETITIVE_SPEC.md: усиление продуктового сценария и архитектуры.
- START_COMPETITIVE.md: основной промпт интегратора.

В архиве нет весов и работающих ASR/диаризации/LLM/YOLO. Примеры — FIXTURE.
80 PASS в reference-results.json относятся только к reference_core.
Нет оснований переносить их на качество распознавания или завершённость кейса.

## Реальные команды reference_core
Из reference_core:
python -m pip install -r requirements.txt
python scripts/verify_reference.py
python -m evidence_core verify fixtures/01_mixed_deadline.json
python -m evidence_core replay fixtures/ledger_mixed.json --at-ms 16000
python -m evidence_core serve --port 8765

Адрес стенда: http://127.0.0.1:8765. Слушает loopback. Не является production-сервисом.
API: GET /api/health; GET /api/capabilities; POST /api/audit;
POST /api/replay; POST /api/export.docx; локальный /openapi.json.

## Единый интерфейс, который должен реализовать интегратор

./project bootstrap --yes
./project doctor --json
./project run --host 127.0.0.1 --port 8000
./project test --level core
./project evaluate --input evaluation/input/ --out reports/run-<id>/
./project verify --profile full --offline --out reports/run-<id>/
./project stop

Эти команды полного приложения пока НЕ существуют в reference_core.
Требуется реализовать, запустить и проверить, а не только добавить их в README.
Можно выбрать эквивалентный кроссплатформенный CLI и задокументировать его.

bootstrap устанавливает инструменты/зависимости, скачивает доступные модели,
проверяет загрузку и тестовый inference. Уважает gated-доступ/лицензии,
не принимает специальные условия за пользователя и не обходит авторизацию.

doctor различает available/imported/loaded/inference_tested. Файл весов на диске
не даёт статуса inference_tested. Печатает конфигурацию без секретов.

verify --profile full не завершает проверку успешным кодом, если обязательный
модуль не был проверен. Предлагаемые коды: 0 — выбранный профиль прошёл;
1 — наблюдаемая проверка провалилась; 2 — не выполнены обязательные проверки
или отсутствует необходимая предпосылка. NOT RUN всегда виден в JSON.

Профиль core может быть успешен без моделей, но должен указывать scope=CORE.
Профиль full требует RU/KK/mixed ASR, диаризацию, поручения, UI и DOCX.
Результат не сворачивается в искусственный единый «балл качества».

## Формат отчёта полного приложения
run_id, revision, started_at, finished_at, hardware, model_manifest_sha256,
data_manifest_sha256, scope, checks[], artifacts[], durations.
Каждая проверка: requirement_id, test_id, status=PASS|FAIL|NOT RUN,
command, exit_code, evidence_path, reason. Никаких PASS без запуска.
Полные чувствительные тексты и аудио в технический отчёт не включать.
Артефакты реальных записей сохраняются только в разрешённом локальном контуре.

## Набор независимых испытаний
Изменить имена, даты, порядок участников, число говорящих, имя файла.
Убрать фразу согласования; добавить её; заменить согласование на отказ.
Добавить сообщение об уже выполненной работе и обсуждение без поручений.
Проверить пустой файл, повреждённое аудио, шум, незнакомое имя, отсутствие срока.

Тестировщик создаёт случаи после фиксации основной логики. Это снижает
подгонку, но не называется полностью слепой независимой оценкой, если команда
видит случаи. Эталоны не передаются модели в runtime и не лежат в lookup-таблице
для результатов. Переименование файла не должно менять содержимое поручений.

Результаты RU, KK и mixed публикуются отдельно; text-only, synthetic audio и
natural audio — отдельными строками. Счётчик тестов не заменяет метрики:
precision/recall задач, полнота корректных action+assignee+deadline,
ошибочные назначения, выдуманные сроки, пропуски и время ручной проверки.
Фактические метрики дополняются объёмом выборки и протоколом сопоставления.
Нельзя заявлять 100% точность по одному выученному примеру.

## Артефакты должны поддерживать утверждения
Снимок экрана подтверждает интерфейс, не качество ASR. Существующая ссылка
подтверждает адресуемость реплики, не её смысл. SHA-256 идентифицирует содержимое,
но без доверенного внешнего механизма не доказывает неизменяемость/авторство.
HTTP health не доказывает загрузку всех моделей. Экспорт JSON→DOCX не доказывает
аудио→DOCX. Каждому утверждению — проверка соответствующего уровня.
