2. РАЗРЕШЕНИЯ НА АВТОНОМНУЮ ПОДГОТОВКУ

Пользователь разрешил интернет для документации, зависимостей, инструментов,
доступных моделей и разрешённых тестовых материалов. Проверь CPU/GPU/RAM/диск,
создай проектное окружение, используй кэш, скачай недостающие веса, проверь каждый
локальный inference и подними все сервисы самостоятельно.

Отсутствие весов — задача подготовки, не повод просить пользователя всё сделать.
Секреты и разрешения не придумывать. Gated-доступ и специальные лицензионные
условия не обходить и не принимать за пользователя. Использовать допустимую
альтернативу, когда она доступна. При объективном блокере записать точную причину.

Не тратить деньги, не удалять чужие данные, не завершать чужие процессы,
не менять глобальные драйверы/firewall/браузерные политики. Не публиковать сервер.
Обработка слушает 127.0.0.1. Не пытаться обходить ограничения среды.

BOOTSTRAP_ONLINE — подготовка из интернета.
RUN_OFFLINE — никакой внешней передачи записей, транскриптов и результатов,
автоскачиваний весов, CDN и облачного inference. Локальный backend ↔ локальная
модель разрешены. Реальные данные не передавать удалённым кодинг-агентам.

3. ОБЯЗАТЕЛЬНЫЙ ПОЛНЫЙ ПУТЬ

Дата/часовой пояс/участники → новый аудио- или видеофайл → локальный ASR →
настоящая диаризация → подтверждение личности говорящих → локальная LLM →
поручения/саммари/вопросы → проверка секретарём → утверждённая версия → DOCX.
Отдельно проверить русский, казахский и смешанную речь. Перевод не заменяет
исходный транскрипт. Говорящий не равен исполнителю.

Предпочтительный стек: FastAPI, SQLite, локальные HTML/CSS/JS, faster-whisper,
локальная диаризация, доступная многоязычная LLM через локальный Ollama,
python-docx. Конкретные модели выбрать по реальному оборудованию и испытаниям.
Не тратить спринт на переписывание рабочего совместимого стека.

Обработка после записи допустима. Показывать реальные стадии и ошибки,
а не выдуманный realtime/проценты. Сохранять промежуточные результаты.

4. СДЕЛАЙ ТРИ СВЯЗАННЫЕ ОТЛИЧИТЕЛЬНЫЕ ФУНКЦИИ

A. «Почему именно так?»
Каждое действие, исполнитель и срок имеют собственное основание.
Кнопка открывает исходные реплики и момент аудио. Структурную валидацию
не называть смысловым доказательством. Неизвестные значения — null.
Человеческая правка имеет отдельное происхождение и историю.

B. «Машина времени поручений»
Извлекай типизированные события create/propose/accept/reject/cancel.
Единый reducer формирует актуальное состояние и временные срезы.
Непринятый/отклонённый перенос не меняет текущий срок. Устаревшее предложение
не перезаписывает новый согласованный срок. Поздние сведения не появляются
в раннем состоянии. Ползунок UI показывает изменения наглядно.

Используй reference_core/evidence_core/ledger.py как стартовую реализацию,
ledger.schema.json — как sidecar. Не ломай snapshot-контракт 1.0 молча:
реализуй явный адаптер и тесты согласованности snapshot/history/export.
Не считай готовым извлечение только потому, что reducer работает на размеченном JSON.
Для live-заявлений отдельно проверять online-prefix extraction.

C. «Перед утверждением уточните»
Показывай неразрешённые реквизиты и конкретные вопросы. Не выдумывай дату,
не назначай выступавшего по умолчанию. Исправление создаёт новую версию;
не превращай правку секретаря в вымышленную реплику.

Камера — только после P0+P1: наблюдаемые зоны и подтверждённый интервал
«Вернулся — догнал». Никакой оценки эмоций, внимательности и продуктивности.

7. ПРОВЕРЬ НА НЕЗНАКОМЫХ СЛУЧАЯХ

Новый файл с другими именами, датами и количеством голосов.
Согласованный перенос; предложение без ответа; явный отказ; отмена;
«не Айдана, а Данияр»; «я уже сделал»; обсуждение без задач;
исполнитель не равен говорящему; отсутствующий срок; смешанная фраза.
Меняй имя файла и порядок списка участников — содержание поручений не должно
подменяться. Не передавай golden-ответы модели и не делай lookup по имени файла.

Unit/contract, text extraction, synthetic-audio E2E, natural-audio E2E,
browser E2E и offline E2E — разные уровни. Нельзя заменить один другим.
RU/KK/mixed отчёт отдельно. Не выдавай сгенерированные казахские эталоны
без проверки владеющим языком человеком за экспертную natural-аудио оценку.

Проверь безопасные ошибки, лимиты файлов, ссылки и пути, XSS, недоверенные
инструкции внутри транскрипта, отсутствие секретов/текста в логах.
LLM не имеет инструментов shell, почты, произвольных файлов или сетевых запросов.

Запусти браузерный сценарий. При ограничении среды не отключай глобальные
политики. Компонентный браузерный тест можно выполнить отдельно, но он
не засчитывается за реальный сетевой E2E.
